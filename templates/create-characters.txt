# Core Instructions

1. **Array Structure & Priority Rules:**
   * Output a single JSON array containing character objects.
   * **Mandatory First Item (`Index 0`):** Must ALWAYS be the **Player Character (PC)**.
   * **Subsequent Items (`Index 1+`):** Optional active **NPCs** extracted or required by the scenario. If no NPCs are present, output only the PC object in the array.

2. **Name Generation & Missing Details Rule:**
   * **Missing Names:** If the user input does not explicitly state a character's name (e.g., "I am an engineer," "a dark lord," "the ship captain"), **YOU MUST GENERATE A UNIQUE, THEMATIC NAME** for that character that fits the tone, culture, and setting defined in <lore>.
   * **Missing Attributes:** If visual traits, personality, skills, or background details are omitted or vague, generate fitting details that align directly with <lore> and <scenario>.

3. **Strict Field Schema Enforcement:**
   Every character object in the array MUST strictly conform to the following properties (all string types):
   * **`name`**: The character's full name or primary title. *(Always populated; generated if missing from input).*
   * **`appearance`**: A comma-separated list containing:
     * Baseline features (e.g., hair color/style, eye color, skin tone, perceived gender, build).
     * Permanent modifications (e.g., bioluminescent markings, scars, tattoos, physical body changes).
     * Active temporary states (e.g., posture, flushing, sweat, dirt, fatigue).
   * **`personality`**: Comma-separated list of core personality traits, temperament, and behavioral tendencies.
   * **`skills`**: Comma-separated list of competencies, technical expertise, combat training, or magical abilities.
   * **`background`**: A concise, summarized origin story explaining who they are and how they connect to the world in <lore> and the current <scenario>.

# Output Format Requirement

Your response must be a single, valid JSON array containing the created characters. Ensure the JSON is syntactically valid (escape any necessary internal quotes or use single continuous strings without raw line breaks). Adhere to the following rules for each field:

**`name` Field Rules:**
- Name of the character
- Include title of the character if present

**`appearance` Field Rules:**
- A comma-separated list of visual appearance tags optimized for image generation (avoid full sentences).
- Mandatory: MUST start with the perceived gender and anatomical baseline tags (e.g., "male", "female", or "androgynous, slender man/woman").
- Include rough age description (e.g., "young adult", "middle-aged", "senior").
- Include build, stature, hair color/style, eye color, and skin color/complexion.
- Max 60 words.

**`personality` Field Rules:**
- A list of key personality traits.
- 3 to 5 comma-separated adjectives.

**`skills` Field Rules:**
- A list of key skills and competencies.
- 3 to 5 comma-separated adjectives.

**`background` Field Rules:**
- A summarized origin story.
- If the character is LGBTQ+, include it naturally in the background story, noting whether it is open or secret.
- Between 50 and 200 words.
